# Community go-live checklist (user steps)

Nothing here is done by the assistant. Never paste a secret in chat, a commit or an issue. Background: README section 3f. Payments checklist: `docs/payments-go-live-checklist.md`.

1. **Upload the roster.** Export the branch member list from IEEE as CSV with columns for member number (8-9 digits), expiry date (YYYY-MM-DD, DD/MM/YYYY or DD-Mon-YYYY) and optionally name (header row optional; max 5 000 rows). Open `/admin/membership` -> Roster -> choose the file, check the preview, upload. Without names every claim goes to manual review.
2. **Add `COMMUNITY_HASH_SALT`.** Cloudflare -> Workers & Pages -> stairway -> Settings -> Variables and Secrets -> type **Secret**, 16+ random characters (or `npx wrangler secret put COMMUNITY_HASH_SALT`). Without it the per-IP form limit is off.
3. **Optional AI pre-screen.** Add the **Secret** `ANTHROPIC_API_KEY`, then add `IEEE_PRESCREEN_ENABLED` = `true` as a **Secret** too (plain dashboard variables are dropped on the next deploy), and optionally `IEEE_PRESCREEN_MODEL`. Set a monthly spend limit in the Anthropic console. Leave it off to use roster + manual review only. It is a hint; a human still approves.
4. **Test each home form** at `/#get-involved` (host an event, partner, feedback incl. one anonymous). Confirm each appears in `/admin/requests`, change a status, download the CSV, then confirm a 6th submission in a day from the same email is refused.
5. **Test chat with two accounts.** A verified member (always eligible) and an attendee with a confirmed registration for a published session. Messages must arrive live both ways without refresh; cut the network briefly and see polling resume. Close, flag, block and unblock from `/admin/chat`. A signed-in user with neither sees the "not available" notice. After the session end time the attendee loses chat access.
6. **Test claim flows** with a second Google account: (a) a roster number that matches -> auto-verified, badge on `/me` and `/u/<handle>`; (b) an unlisted number + card photo -> appears in the review queue as pending, "Show proof", approve and reject; (c) the classmate case: claim a number already held by another account -> the same "needs review / proof required" outcome, never a hint that it is taken. Approve with a date within 30 days to see the renewal prompt; revoke.
7. **Live-only verifications** that cannot run offline: Realtime push end-to-end with RLS (another user's or an ineligible tab receives nothing), signed upload enforcement for the `ieee-proof` bucket (cannot write another user's path, a wrong type or over 5 MB), real response headers (`/me/*` and `/admin/*` redirect when signed out; `/robots.txt` disallows `/me/` and `/admin/`; the sitemap lacks the new routes).
8. **Retention:** the purge runs from the cron tick only while payments or sync are on. Until then run `select private.purge_community();` monthly in the Supabase SQL editor and delete the returned `proof_paths` in Storage -> `ieee-proof`.
9. **Reminder:** email notifications stay off until a sending domain exists; Workers **Paid** is still recommended (10 ms CPU on Free).
